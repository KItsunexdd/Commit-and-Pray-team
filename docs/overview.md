# Jana Address простыми словами

Документ для тех, кто хочет понять, что мы сделали, как это устроено и где что лежит. Специальных знаний не нужно: незнакомые слова объяснены в словаре в конце.

Состояние на 18.10.2026.

---

## 1. Что где лежит

- В репозитории — всё, что нужно для работы сервиса: код, справочник (Git LFS), собранный интерфейс, документация.
- Вне репозитория из-за размера: train (6000 синтетических строк) и архив Docker-образа `jana-address.tar`. Контрольная сумма архива лежит в `jana-address.tar.sha256`.

## 2. Что за задача

Клиенты Jana Post пишут адрес доставки одной строкой, как им удобно:

> `66квартал 12дом 69квартира`
> `Туран 55/6 магазин береке 4подьезд 9этаж`
> `город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70`

Из такой строки нельзя посчитать зону доставки или построить аналитику по городам, а курьер звонит клиенту уточнять квартиру и подъезд.

**Наш сервис раскладывает строку на 14 полей:**

| Поле | Пример |
|---|---|
| `id`, `raw_address` | возвращаются как пришли |
| `province` — область | Алматы |
| `city` — город | Алматы |
| `district` — район | Ауэзовский |
| `living_area` — жилой массив | Пришахтинск |
| `street_type` — тип улицы | микрорайон |
| `street_name` — название | Аксай 3а |
| `house` — дом | 59 |
| `apartment`, `entrance`, `floor` — квартира, подъезд, этаж | 70 |
| `landmark` — ориентир | магазин береке |
| `confidence` — уверенность | 0,82 |

**Как нас оценивают:**

| Доля | За что |
|---|---|
| 45% | Точность на скрытом наборе жюри: адрес 60% (область, город, улица, дом), детали 25% (квартира, подъезд, этаж), справочные поля 15% (район, жилой массив) |
| 30% | Инженерия: справочник, восстановление полей, архитектура, код |
| 15% | Интерфейс |
| 10% | Презентация |

**Жёсткие условия:** на проверке нет интернета, всё запускается в Docker, контейнер должен стартовать не дольше 3 минут, 1000 адресов — обработать не дольше 5 минут.

## 3. Как это устроено (одна картинка)

```
 Жюри или системы Jana Post ─► REST API ─┐
                                         ├─► Парсер ─► Справочник адресов (SQLite)
 Оператор в браузере ───► Веб-интерфейс ─┘
 └──────────── всё внутри одного Docker-контейнера, интернет не нужен ────────────┘
```

**Путь одного адреса:**
1. Строка приходит в **API** (из файла жюри или из интерфейса).
2. **Парсер** чистит строку, находит части адреса и собирает лучший вариант разбора.
3. Парсер **сверяет** найденное со **справочником**: правильный ли город, есть ли такая улица, в каком районе этот дом.
4. API возвращает 14 полей. Интерфейс дополнительно показывает, какое слово строки стало каким полем и откуда взято значение: из строки или из справочника.

## 4. Части проекта

### 4.1. Парсер — `AddressParser/`
Программа на Python, только стандартная библиотека, без машинного обучения. Работает по правилам:

| Шаг | Что делает | Пример |
|---|---|---|
| Очистка | Нормализует пробелы, убирает невидимые символы по краям, разделяет склейки | `Жандосова58кв12` → `Жандосова 58 кв 12` |
| Маркеры | Слова-подсказки на русском, казахском и латинице связывают числа с полями | `кв`, `подъезд`, `мкр`, `көшесі`, `пәтер`, `flat` |
| Варианты | Строит несколько вариантов разбора и выбирает лучший | `26кв31` → дом 26, квартира 31 |
| Справочник | Проверяет город и улицу, восстанавливает район и область; если города в строке нет, а улица с этим домом есть ровно в одном населённом пункте — подставляет его | `Аксай 3а` → Ауэзовский район; `Туран 55/6` → Астана |
| Результат | Улица и номера — ровно как в строке, опечатки не исправляются. Если источники района противоречат друг другу, район остаётся пустым. Из нескольких претендентов на одно поле выбирается наиболее вероятный, а уверенность снижается | — |

Подробно: [`AddressParser/README.md`](../AddressParser/README.md).

### 4.2. Справочник адресов — `artifacts/address_db/runtime/v002-territories/address_runtime.sqlite`
Файл базы данных на 66 МБ, собран нашими скриптами из открытых источников: **OpenStreetMap** (снимок 15.10.2026) и **КАТО** — государственного классификатора (18.09.2026).

| Что внутри | Сколько |
|---|---|
| Регионы | 20 |
| Города | 90 |
| Районы | 195 |
| Улицы | 58 803 |
| Микрорайоны и жилые массивы | 11 607 |
| Дома | 1 099 024 |
| Территории (микрорайоны, ЖК) с районом по контуру | 1 122 |

Как восстанавливается район, если его нет в строке, по порядку надёжности:
1. район написан в строке;
2. точный дом есть в справочнике;
3. соседние дома той же улицы;
4. не меньше 95% площади микрорайона лежит в одном районе.

Названия областей — после реформы 2022 года (Абайская, Жетысуская, Улытауская, Конаев). **Ограничение:** в OpenStreetMap нет границ районов Караганды, там район берётся только из строки.

Рядом два вспомогательных файла парсера: `artifacts/baseline/neighbours-v1.sqlite` (соседние дома) и `artifacts/baseline/v3/uniform-v3/uniform.sqlite` (улицы, целиком лежащие в одном районе). Все три базы хранятся через Git LFS.

### 4.3. REST API — `app/`
Небольшой сервер на FastAPI:

| Адрес | Для кого |
|---|---|
| `POST /api/parse/batch` | Для жюри: файл адресов → файл результатов строго в формате организаторов |
| `POST /api/ui/parse` | Для интерфейса: результат и подсветка |
| `GET /api/info` | Числа справочника для экрана «Как это работает» |
| `GET /api/health` | Проверка, что сервис запущен |
| `GET /api/docs` | Документация, работает без интернета: можно отправить пример запроса прямо со страницы |

Одна испорченная запись не ломает весь файл: она получает пустой разбор, остальные обрабатываются. Контракт: [`docs/api.md`](api.md).

### 4.4. Веб-интерфейс — `web/`
React-приложение, собранная версия лежит в `web/dist`, её отдаёт тот же сервер:
- цифровая карта Казахстана: подлёт к найденной области;
- разбор адреса с подсветкой полей прямо в строке и пометкой источника;
- проверка JSON-файла с ручной правкой, выгрузка в JSON, Excel и CSV;
- аналитика по файлу;
- светлая тема в цветах Jana Post и тёмная тема;
- режим без карты;
- версия для телефона;
- работа без интернета: шрифты и карта внутри сборки.

Подробно: [`web/README.md`](../web/README.md).

### 4.5. Docker
`Dockerfile` собирает один образ: Python, парсер, три базы, интерфейс и API, всего 330 МБ. Готовый образ сохранён в файл `jana-address.tar` (71 МБ). Его можно перенести на компьютер без интернета и запустить.

### 4.6. Проверка качества
| Набор | Где | Строк | Что это |
|---|---|---|---|
| `Samples/` | репозиторий | 1 + 4 | Пример организаторов |
| dev | `datasets/evaluation/gold/T3.1_A1/` | 300 | Синтетика с двойной разметкой, открыта разработчикам |
| test и calibration | закрыты | 300 + 200 | Закрытая часть того же эталона. При разработке не открывалась, иначе оценка перестаёт быть честной |
| train | вне репозитория | 6000 | Синтетика по 27 шаблонам для регрессии |
| fresh-v1 | вне репозитория | 123 | Адреса на реальных улицах, написанные вручную отдельно от разработки |

## 5. Как запустить

**Из готового файла образа** (интернет не нужен):

```bash
docker load -i jana-address.tar
docker run -d -p 8000:8000 --name jana-address jana-address:1.0.0
```

**Из репозитория:**

```bash
git lfs install
git clone https://github.com/KItsunexdd/Commit-and-Pray-team.git
cd Commit-and-Pray-team
docker compose up -d --build
```

Затем открыть http://localhost:8000. Пример запроса и остальные команды — в [`README.md`](../README.md).

## 6. Цифры

| Что | Результат |
|---|---|
| Старт контейнера без сети | около 2 с (лимит 3 мин) |
| 1000 адресов | около 0,5 с (лимит 5 мин); на 1 ядре и 512 МБ памяти — 0,4 с, пиковая память 31 МБ |
| Новые адреса на реальных улицах, которых парсер не видел (fresh-v1), версия v5 | **93,6%** (95% интервал 87,6–97,9%) |
| «Живые» записи на реальных улицах Астаны, Алматы, Шымкента (504: приклеенный город, город в конце улицы или в хвосте, опечатка в районе, падеж улицы, без города, улица из нескольких объектов OSM), v11 → v12 | **71,4% → 99,6%** записей без ошибок; район из справочника, когда его нет в строке, заполняется в 4 из 5 случаев |
| Массовая проверка: 20 000 реальных домов из справочника, 600 населённых пунктов, 34 тысячи однозначных записей (v9) | **99,55%**, ноль падений; в v10 дополнительно исправлены инициалы в названиях улиц |
| Второй независимый набор fresh-v2 (75 адресов), версия v7 → v9 | **95,1% → 100%**. По этому набору исправлялись классы ошибок (без самих строк), поэтому 100% — подтверждение исправлений, а не новая независимая оценка |
| Закрытый синтетический test (300 строк), версия v7 | **100%**, 1188 из 1188 ячеек. На dev и train ответы v9 совпадают с v7 строка в строку |
| dev и train, версия v10 | по 100%, но эти наборы разработчик видел: это проверка на регрессию, а не оценка качества |

**Как читать эти цифры:**
- **fresh-v1** — самая честная оценка: реальные улицы, составлены независимо, разработчик их не видел и правила под них не подгонялись.
- **Закрытый test** разработчик тоже не видел, проверка проведена по заранее зафиксированному протоколу, набор открывался один раз. Но test синтетический и построен по тем же 50 шаблонам, что dev. Он показывает, что парсер не подогнан под конкретные строки dev, но не проверяет новые способы записи.
- **Уверенность** (`confidence`) — внутренний рейтинг, а не вероятность. Настроить её по закрытому набору calibration не удалось: на нём не нашлось ни одной ошибки, а без ошибок калибровку строить нельзя.
- **Самый большой риск по метрике** — форма названий трёх новых областей. Если жюри ждёт официальную форму КАТО («область Абай»), а не «Абайская область», результат на test снижается до 93,3%. Переключатель формы есть в справочнике, выбор зависит от ответа организаторов.
- **Чего эти цифры не означают:** «99–100% на любых адресах» (это наборы, построенные по известным шаблонам), «размечено людьми вручную» (эталон синтетический), «районы Караганды восстанавливаются» (нет границ в OSM).

## 9. Словарь

| Слово | Что значит |
|---|---|
| Парсер | Программа, которая раскладывает строку адреса на поля |
| Справочник | Наша база адресов Казахстана: города, улицы, дома, районы |
| OSM, OpenStreetMap | Открытая карта мира, которую заполняют пользователи. Отсюда улицы, дома и границы |
| КАТО | Государственный классификатор административно-территориальных объектов Казахстана: официальные области, районы, населённые пункты |
| SQLite | Формат базы данных в одном файле, без отдельного сервера |
| API, REST API | Способ для программ обращаться к сервису: отправил адреса — получил результат |
| Docker, образ, контейнер | Упаковка программы со всем нужным внутри. Образ — упаковка, контейнер — запущенная упаковка |
| Git, GitHub, ветка, PR | Система хранения версий кода. PR (Pull Request) — предложение влить изменения в основную ветку |
| Git LFS | Дополнение к git для больших файлов, у нас для баз SQLite |
| Эталон, разметка | Адреса с заранее известными правильными ответами, по ним считаем точность |
| dev, test, calibration | Части эталона: dev видят разработчики, test и calibration закрыты для честной оценки |
| train | Большой набор для проверки, что исправления ничего не сломали |
| Регрессия | Когда после исправления ломается то, что раньше работало |
| Span, подсветка | Позиция поля в исходной строке, чтобы показать его цветом |
| confidence | Насколько сервис уверен в разборе, от 0 до 1. Низкая — стоит проверить вручную |
