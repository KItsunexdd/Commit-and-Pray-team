# API Jana Address

Сервис слушает порт `PORT` (по умолчанию `8000`), все пути начинаются с префикса `API_PREFIX` (по умолчанию `/api`). Оба значения задаются переменными окружения в `docker-compose.yml`. Веб-интерфейс собран с префиксом `/api`: если префикс поменять, интерфейс нужно пересобрать с тем же `VITE_API_BASE`.

Интерактивная документация OpenAPI: `GET /api/docs`. Она отдаётся из файлов внутри образа и работает без интернета; схемы запросов и пример уже заполнены, запрос можно отправить прямо со страницы.

Тело запроса больше `MAX_BODY_BYTES` (по умолчанию 64 МБ) отклоняется с кодом `413` до разбора JSON — и для JSON, и для формы multipart, в том числе при потоковой передаче без `Content-Length`. Строка с непарным суррогатом Unicode не роняет пакет: такие значения возвращаются как есть, экранированными по правилам JSON.

Одновременные запросы разбора встают в общую очередь к одному прогретому потоку (`PARSE_WORKERS`, по умолчанию 1): так 20 параллельных пакетов по 1000 адресов обрабатываются примерно за 13 с вместо 41 с при конкуренции потоков.

## Форматы

**Входная запись**
```json
{ "id": "rec_00417", "raw_address": "город Алматы/Алматы қаласы, Мкр Аксай 3а, 59, кв 70" }
```
`id` может повторяться. Порядок записей в ответе всегда совпадает с порядком во входных данных.

**Результат разбора (`AddressResult`)** — всегда ровно 14 полей, ни один ключ не пропускается:

| Поле | Тип | Что содержит |
|---|---|---|
| `id` | string | Из входной записи, без изменений |
| `raw_address` | string | Исходная строка, без изменений |
| `province` | string \| null | Область («Актюбинская область») или город республиканского значения («Алматы») |
| `city` | string \| null | Город или населённый пункт, без «город», «пос.» и казахской половины |
| `district` | string \| null | Район без слова «район» |
| `living_area` | string \| null | Микрорайон или ЖК, если улица указана отдельно |
| `street_type` | string \| null | Полным словом: улица, проспект, микрорайон, переулок, квартал… |
| `street_name` | string \| null | Название без типа, ровно как в строке |
| `house` | string \| null | Номер дома с дробью и литерой: «1/2», «12а» |
| `apartment` | string \| null | Только номер |
| `entrance` | string \| null | Только номер |
| `floor` | string \| null | Только номер |
| `landmark` | string \| null | Ориентир из строки: «магазин береке» |
| `confidence` | number | Уверенность разбора, от 0 до 1 |

Если разобрать запись не удалось, все адресные поля равны `null`, а `confidence` низкий.

## Эндпоинты

### `POST /api/parse/batch`
Пакетный разбор в строгом формате.

Тело — один из вариантов:
- `application/json`: массив записей `[...]` или обёртка `{ "records": [...] }`;
- `multipart/form-data`: JSON-файл того же формата в поле `file`.

Ответ: `AddressResult[]` в исходном порядке, по одному результату на каждую входную запись.

- Запись без строки `raw_address` (или не объект) не роняет пакет: она получает пустой разбор, `id` и `raw_address` возвращаются как пришли.
- Адрес длиннее `MAX_ADDRESS_CHARS` (512 символов — в несколько раз длиннее реальных адресов) разбирается по первым символам, в ответе остаётся целиком. Так вырожденная строка в тысячи символов не занимает очередь разбора надолго.
- Тело не JSON или не массив и не `{"records": [...]}` → `422`. Больше `MAX_BATCH_RECORDS` (100 000) записей → `422`.

```bash
curl -X POST http://localhost:8000/api/parse/batch \
  -H "Content-Type: application/json" \
  --data-binary @sample_input.json
```

### `POST /api/parse`
Одна строка: `{ "id": "...", "raw_address": "..." }` → один `AddressResult`. `id` можно не передавать.

### `POST /api/ui/parse`
Разбор для веб-интерфейса: к результату добавляются пояснения.

Тело: `{ "records": [ { "id": "...", "raw_address": "..." } ] }`

Ответ:
```json
{
  "items": [
    {
      "result": { "...": "AddressResult" },
      "explain": {
        "spans": [ { "field": "street_name", "start": 32, "end": 40 } ],
        "sources": { "street_name": "string", "district": "dictionary" }
      }
    }
  ]
}
```
- `spans` — позиции найденных полей в `raw_address`, `end` не включается. Позиции в единицах UTF-16, как считает JavaScript: эмодзи занимает две позиции.
- `sources` — откуда взято значение: `string` (из строки) или `dictionary` (из справочника).
- `explain` может быть `null` или неполным.
- `id` и `raw_address` каждой записи — строки, иначе `422`. В одном запросе не больше `MAX_UI_RECORDS` (500) записей.

### `GET /api/info`
Сведения о справочнике для экрана «О справочнике». Числа считаются по SQLite при старте сервиса:
```json
{
  "version": "1.0.0",
  "gazetteer": {
    "sources": [
      { "name": "OpenStreetMap", "url": "https://www.openstreetmap.org", "date": "2026-10-15" },
      { "name": "КАТО — классификатор административно-территориальных объектов", "url": "https://stat.gov.kz", "date": "2026-09-18" }
    ],
    "counts": { "regions": 20, "cities": 90, "districts": 195, "streets": 58803, "living_areas": 11607, "houses": 1099024 }
  },
  "metrics": []
}
```
`metrics` заполняется, только если рядом лежит `data/metrics.json` (путь задаётся `JANA_METRICS`) с результатом оценки на закрытой выборке: `[{ "version": "...", "score": 0.0, "address": 0.0, "details": 0.0, "reference": 0.0 }]`.

### `GET /api/health`
```json
{ "status": "ok", "version": "1.0.0" }
```
Пока справочники открываются при старте, ответ `503` и `"status": "starting"`. Обычно это меньше двух секунд.
