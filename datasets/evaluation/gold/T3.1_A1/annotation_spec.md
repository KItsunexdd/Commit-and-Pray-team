# Инструкция разметки JanaAddress — версия 1.1

Версия 1.1 зафиксирована до выпуска T3.1 и до независимой разметки, 17.10.2026 (UTC+5). Версия 1.0.0 и выпуск T2 сохранены без изменений. Статус: интерпретация ТЗ до ответа организаторов, не принятый gold. Основания: разрешённый `audit_tz.txt`, Samples и Notes. Публичные примеры ниже — учебные, не ответы к закрытым строкам. Исправление смысла требует новой версии инструкции, списка затронутых записей и повторной разметки до сравнения систем.

## Формат и границы

Одна строка JSONL — одна запись. `record_key` уникален внутри выпуска и не является входным `id`. `expected` содержит ровно 11 адресных полей: province, city, district, living_area, street_type, street_name, house, apartment, entrance, floor, landmark. `id`, `raw_address` и `confidence` в expected не входят. Полный внешний ответ по Samples содержит 14 ключей; raw находится на верхнем уровне разметки, входные id — в отдельном input-массиве. Ответы сопоставляются только по позиции, даже при повторении id.

Все значения expected — непустая строка или null. `origin` содержит те же 11 полей, значения explicit / inferred / absent. `spans` содержит те же поля и списки объектов `{start,end,transform}`. Интервалы [start,end) — индексы кодовых точек Python str, не UTF-8 байтов и не UTF-16. Повторённое значение может иметь несколько интервалов; каждый отдельно преобразуется в одно и то же expected. При absent или inferred список пуст. Служебные невидимые символы внутри значения входят в интервал. Снаружи значения пробелы, запятые и маркеры не входят. Unicode-нормализация перед определением границ запрещена.

Допустимые transform:

- `identity`: raw[start:end] равен expected буквально.
- `street_type`: явный маркер заменяется на полное слово по словарю evaluation_config.json. Слитный маркер имеет собственный интервал.
- `province_order`: `область Актюбинская` → `Актюбинская область`; для обычных прилагательных перестановка начального слова «область». Для Абай/Жетісу/Ұлытау механическая перестановка запрещена.
- `province_canonical`: только для province; точное сопоставление поверхности в named_province_forms из evaluation_config.json и возврат canonical.
- `province_official`: только для province в альтернативной гипотезе; по той же поверхности вернуть official. Границы исходного текста не меняются.

При отсутствии span выводить explicit нельзя. Один интервал может поддерживать несколько полей только при явно описанном правиле; в текущем выпуске province из названия города республиканского значения помечается inferred, а не вторым explicit.

## Извлечение

1. street_name, house, apartment, entrance, floor, landmark, district и living_area сохраняют написание исходной строки, регистр, внутренние пробелы, опечатки, латинские двойники, невидимые знаки и падеж. `Турксибского района` → district `Турксибского`. Числа всегда строки, включая `01`, `-1`, `12а`, `1/2`. Нельзя достраивать окончание или исправлять букву.
2. city: убрать внешний маркер «город», «г.», «пос.», «қаласы», «қ.». В двуязычном дубле через / выбрать русскую половину; казахская половина не является вторым городом. Повтор города не создаёт новую запись. Если одинаковое русское имя повторено, сохранить оба подтверждающих интервала.
3. **Казахский город без русской половины:** сохранить казахское имя как explicit, без транслитерации: `Өскемен қаласы` → city `Өскемен`. Это заранее выбранная интерпретация, поскольку требование «без казахской половины» касается дубля. Альтернатива — русское справочное имя; её влияние считать отдельно. Случаи с различными ru/kk именами помечаются `kk_city_policy`. Русификация не считается identity-преобразованием.
4. province: явно написанную область привести к каноническому русскому значению. Для трёх новых областей использовать строго **Абайская область**, **Жетысуская область**, **Улытауская область**. Механические смеси «Абай область», «Жетісу область», «Ұлытау область» запрещены как expected, в том числе в inferred и во вложенных альтернативных гипотезах. Для обычных прилагательных действует `область Актюбинская` → `Актюбинская область`. Для города республиканского значения province равен имени города. Если отдельного обозначения области нет, province inferred только при однозначной связи с выбранным публичным именем города; в метрику извлечения не входит. В синтетике не восстанавливать district, living_area, street_type или адресную принадлежность улицы по сочетанию выдуманных компонентов.
5. street_type — полное слово по явному маркеру: улица, проспект, микрорайон, переулок, квартал, бульвар, проезд. При отсутствии маркера null/absent; название само по себе не доказывает тип. `көшесі` → улица, `даңғылы` → проспект, `шағын аудан` → микрорайон. `ЖК` задаёт living_area при отдельно указанной улице; без улицы политика ЖК не определена, случай требует альтернатив, нельзя автоматически назвать его улицей.
6. Микрорайон без отдельной улицы занимает street_name/street_type; living_area null. При отдельной улице микрорайон/ЖК занимает living_area. Номер микрорайона входит в его имя; номер дома — отдельное поле. `мкр Учебный 7, дом 28` → street_name `Учебный 7`, house `28`. `мкр Учебный 7, ул. Примерная, дом 28` → living_area `Учебный 7`, street_name `Примерная`.
7. **Корпус, до генерации:** один house включает буквальное непрерывное обозначение от номера дома до номера корпуса включительно: `дом 27 корп. 3` → house `27 корп. 3`; `дом 27к3` → `27к3`; `дом 27 корпус Б` → `27 корпус Б`. Маркер «дом» исключён, внутренний маркер корпуса сохранён: в контракте отдельного поля нет. Не превращать `27 корпус 3` в `27/3`. Для проверки чувствительности выделить корпус в тег `corpus_policy`, альтернативно оценить только базовый номер. Эта альтернатива не является принятой основной меткой.
8. Ориентир включает предметное слово: `магазин Рассвет`, `Qazpost Западный`. Внешние связки «возле», «ориентир:» не входят; цифры внутри ориентира не становятся номером дома/квартиры. Эмодзи как часть обозначенного ориентира сохраняется. Отдельные инструкции курьеру не являются landmark автоматически.
9. Отсутствие поля — absent/null, а не пустая строка. Если строка содержит лишь город, детали не придумывать. Пустая/пробельная строка допустима как контроль отсутствия данных. Не выводить город из улицы, если его нет в строке.
10. Неразрешённые числа без маркеров, два конкурирующих города, дробь с пробелами и другие случаи с несколькими разумными прочтениями фиксируются в ambiguity. expected является только репрезентативной гипотезой генератора. Каждая alternative — согласованный patch из expected, origin, spans; заменяются все перечисленные поля вместе. Поля перечисляются в `fields`; `reason` обязателен. `kind=unresolved` исключает эти поля из основной метрики до арбитража; `kind=policy_sensitivity` не исключает, но даёт отдельный сценарий. Нельзя выбирать по предсказанию парсера или принимать разные несовместимые поля из разных альтернатив.

## Нормализация и метрика

Использовать evaluation_config.json версии 1.1. Сначала lower(), затем удалить символы категории Unicode P*, затем схлопнуть Unicode whitespace (split/join). Не удалять Cf (невидимые форматирующие), не применять NFKC, casefold, ё→е, исправление опечаток или падежей. **Для номеров** в основном локальном варианте сохранить `/` и `-`, чтобы `2/7` не совпало с `27`, а `-1` с `1`. Буквальное удаление всей пунктуации ТЗ считать параллельным режимом `judge_literal`; точный набор пунктуации жюри неизвестен. Сравнение raw и id в контракте всегда буквальное, без нормализации.

Для каждого поля сначала accuracy по всем eligible записям (origin explicit, expected non-null, поле не unresolved). Затем среднее field accuracy по непустым полям группы. Затем веса 0.60/0.25/0.15; отсутствующие целиком группы исключаются, оставшиеся веса перенормируются. Нельзя усреднять по записям вместо этого алгоритма. Если нет ни одной оцениваемой группы, итог null, не 0 и не 1. Параллельно micro accuracy всех eligible ячеек и доля записей с полным совпадением eligible полей внутри каждой группы. Пустая группа записи не участвует; отдельно показать число записей с частичной/полной представленностью группы. street_type, landmark, confidence не входят в эти метрики.

Лишнее непустое значение при origin absent — отдельный счётчик и доля от absent ячеек, по полям и суммарно; null→null не увеличивает accuracy. Это диагностика недоказанного заполнения, а не автоматическое снижение основного балла: ТЗ допускает справочное обогащение, а в ответе нет его происхождения. inferred поля имеют отдельную accuracy, не смешанную с извлечением. Невалидный тип не нормализовать в строку и не засчитывать.

Чувствительность: отдельно опубликовать число строк/ячеек, затрагиваемых каждой policy, число исключённых unresolved ячеек и изменение числа eligible. При настоящих предсказаниях вычислить основной режим, judge_literal и каждый согласованный альтернативный сценарий отдельно. Без предсказаний нет эмпирической разницы качества; структурные доли не называть выигрышем. Набор альтернатив не является правилом «принимать любой ответ».

## Независимость разметки и пилот

Независимый разметчик получает только эту spec, config, raw/{dev,calibration,test}.jsonl и pilot_manifest.json. Ровно первые 100 test строк — пилот. Разметчик не получает labels, генератор, input sidecar, coverage с примерами, source selection или отчёт с примерами. Генерация набора не является независимой проверкой самой себя. Арбитр после независимой разметки фиксирует gold, его hash и spec до доступа к предсказаниям. Разработчику разрешены spec/config и открытый dev после передачи; calibration/test, их raw, шаблоны генератора и варианты остаются закрыты.

Связанные варианты/переводы/точные дубли одного адреса имеют единый entity_group и source_group и находятся в одной части. Общие template_family разрешены между частями, это не независимость шаблонов; публикуется число семейств, повторов и кластеров. Для последующей статистики основная единица ресэмплинга — entity_group; дополнительная чувствительность по template_family обязательна. Модель, кандидаты, gold, метрика, правило выбора и доступы фиксируются до открытия test. Генератор не запускает и не читает парсер. Ни один сгенерированный файл нельзя автоматически объявлять принятым gold.

Все адреса синтетические. Имена взяты из публичного локального источника; сочетания улица/город/дом и детали могут быть вымышлены. Набор проверяет извлечение, а не географическую достоверность или реальные частоты Jana Post.

## Изменения 1.1 и чувствительность названий областей

Канонические пары заданы исправлением до независимой разметки: Абайская область ↔ область Абай; Жетысуская область ↔ область Жетісу; Улытауская область ↔ область Ұлытау. Правило применяется и к явно указанному, и к восстановленному province. Origin сохраняется: нормализация названия сама по себе не делает explicit значением inferred.

Для каждого основного expected с одной из этих трёх областей добавить ambiguity с kind=policy_sensitivity, policy=province_name_policy, fields=[province], reason="до ответа организаторов". Альтернатива содержит официальную форму, то же origin, при explicit — тот же span с transform=province_official, при inferred — пустой список. Основная явная метка использует province_canonical. Формы старого выпуска, оставленные внутри raw как шумный пользовательский ввод, разрешены лишь как поверхности точной таблицы преобразования; в expected они запрещены.

Если новая область появляется только в альтернативном городе unresolved-гипотезы, не добавлять конфликтующую независимую замену province поверх основного города. Внутри того же unresolved-случая сохранить две цельные альтернативы: выбранный город с канонической областью и тот же город с официальной областью. Метаданные alternative_policies указывают индекс официальной альтернативы, индекс её канонической основы, kind=policy_sensitivity, policy=province_name_policy и reason="до ответа организаторов". Нельзя сочетать область этой ветки с основным другим городом. До разрешения города эти поля остаются исключёнными из основной метрики.

Чувствительность считать отдельно: строки/ячейки с основной меткой; explicit и inferred; изменённые нормализованные значения; неизменность знаменателей; верхняя граница изменения основного балла; доля затронутых inferred province; отдельно условные варианты unresolved. Последние не прибавляются к основным 124 строкам и не получают выдуманной разницы качества. Без прогнозов наблюдённая разница равна null.

Для новых населённых пунктов поле city по-прежнему сохраняет написание имени из raw. Дополнительные внешние маркеры: «с.», «пос.», «ауылы», «кенті» исключаются из city, как «город» и «қаласы». Конаев/Қонаев и Отеген батыр/Отеген батыра — варианты исходного написания, а не повод исправлять извлечённый city. Принадлежность выбранного населённого пункта Алматинской области проверяется по цепочке родителей разрешённого локального источника; одноимённый Боралдай из другой области не подставляется.

Изменения проходят повторную генерацию разметки и структурную проверку в новом выпуске. Пилот заново фиксируется по первым 100 строкам этого выпуска, даже если позиции сохранились. Размеры 300/200/300, веса, числовая нормализация, единицы span и статус t_only не меняются.
