# JanaAddress: базовый офлайн-парсер

Финальная версия — v12, справочник v002-territories: train **100.00%**, dev **100.00%** на просмотренных
синтетических наборах разработки. Это не оценка на новых адресах. Город с маркером
распознаётся независимо от запятых; поддержаны сельские, постфиксные, латинские
и слитные маркеры. Без маркера допускаются только типы city/town, включая
казахские и исторические имена. В текущем runtime есть city, но нет town;
settlement не считается городским типом автоматически. Для села/аула/посёлка
нужен маркер. Явный город или отдельный сегмент с городом прекращает дальнейший
поиск города без маркера. Целые городские сегменты проверяются раньше префиксов
улиц. Сохраняются многословные имена, постфиксные типы и «р-н» после района.
Номер сразу после имени, детали и ориентир не доказывают наличие города;
числовая адресная часть допускается со своим уличным маркером (например мкр).
«г» без точки требует известного имени. Поддержаны д/под/эт и
дефис перед маркером детали, в том числе после ориентира. Парсер не читает
train; его используют только тесты и оценщик. Неохваченные фрагменты видны
в diagnostics.uncovered и reasons, а исходная строка сохраняется целиком.

С v6 Unicode Cf удаляется с краёв
интервалов вместе с пробелами и `,;:.`. Cf между маркером и числом не мешает
распознать номер; Cf после номера не переносит дом в название улицы.
Внутренние Cf (например `Лу\u200bнная`) сохраняются. Spans указывают на очищенные
границы в неизменённой исходной строке. SQLite и правила вывода района прежние.

V7 поддерживает склейки улицы с домом и деталями, дефис в «Таугуль-1»,
тире с пробелами как разделитель, литеру перед дробью (`2а/7`), сокращение
`обл.`, варианты `етаж`/`этж`/`этаж.`, `кв-ра`/`квар.`/`подъез` и тип
`шағын ауданы`. Обратные числовые записи сохраняются. Справочный район
одинаково очищается от «район»/«ауданы» при любом методе вывода.
Казахское имя города без русского дубля и явно маркированное сельское имя
сохраняют написание строки. Профиль областей остаётся project.

V8 отделяет телефон, начальные индекс и страну; распознаёт `қ.`,
`мкрн`/`м-н`/`мкр-н`, `№` после числового маркера и латинские типы улиц.
Корпус входит в house целиком. Запись `12/1-40` после улицы без явной квартиры
даёт house=`12/1`, apartment=`40`, reason=`house_apartment_hyphen` и пониженный
confidence. Ориентир после дома отделяется от улицы. Отдельный жилой массив
выделяется по маркеру либо точному address_area в том же городе, когда отдельно
указана улица/микрорайон; голое число сохраняет роль дома. Исторические и
латинские города возвращаются как написаны; справочный ID определяет область.
Телефон, страна и индекс остаются в raw_address, их интервалы — в
`diagnostics.ignored`. Ключи record и интерфейс spans/sources прежние.

V9 снимает маркеры населённого пункта перед именем и после него, включая
приставленные `г.Алматы`, `пос.Боралдай`, `г.Нур-Султан` и `Алматы г.`.
Точка отделяет сокращение от имени без обязательного пробела. Полные маркеры
сохраняют границу слова. Spans city содержат только имя; явное написание,
справочный ID и проектный профиль области сохраняются. Маркер после улицы
и повтор города не переосмысляются как постфикс предыдущего имени.

V10 различает заглавные инициалы улицы `С.`, `Г.`, `П.` и маркеры
населённого пункта по уличному контексту. Инициал сохраняется в street_name
вместе с точкой и исходным пробелом. Известные населённые пункты после
`Г.Алматы`, `с.Аксу`, `п.Отеген батыр` продолжают распознаваться.

V11 распознаёт известный город в конце части строки после дома. Короткий
нераспознанный хвост после номера не поглощает дом: текст остаётся в
`diagnostics.uncovered`, district остаётся null, confidence снижается.
Границы «строчная → Заглавная + строчная» учитываются при токенизации,
хвостовом и обратном поиске; raw_address и вырезаемые значения не переписываются.
Литеры домов и одиночные заглавные не создают новых границ слов.

V12 уточняет одноимённые геонимы по наличию указанного дома: ровно одна
подтверждённая связь разрешает вывод района. Город в конце названия улицы
отделяется только при подтверждении оставшейся улицы в этом городе и при
отсутствии другого явного города. Поддержаны пробел и граница склеенных слов.
В установленном городе допускается однозначная сверка одной опечатки
(вставка, потеря, замена, соседняя перестановка) и падежной формы.
Имена короче трёх символов не проверяются на опечатки. Значение и spans
остаются исходными; подтверждение хранится в `evidence[field].confirmation`.
Например, район «Сырыарка» в Астане остаётся «Сырыарка» с source=string.
Без найденного города поиск с опечаткой не запускается. Прежний обратный
поиск v11 по точной паре улица/дом, включая формы первого имени, сохраняется.

Если city отсутствует, вариант B ищет street_name + house по всему runtime.
Ровно один населённый пункт даёт city/province с методом `unique_street_house`,
origin=inferred, source=dictionary и без spans. Несколько совпадений либо ноль
оставляют city пустым; явная область не используется для сокращения множества
кандидатов. У многословных имён проверяются также формы первого слова с/без
окончания «а»; написание street_name не меняется. Уникальность означает
однозначность внутри текущего справочника, а не полноту его географического
покрытия. Поэтому «Туран 55/6» теперь выводит Астану; «Абая 12» остаётся без города.
Список кандидатов доступен в `diagnostics.reverse_locality`.

Новые команды, из корня проекта:

```text
python -B -m AddressParser.evaluate --dataset train --out artifacts/baseline/new-train-run
python -B -S -m unittest AddressParser.test_regressions -v
python -B -S -m AddressParser.benchmark --workload regression --out artifacts/baseline/new-regression-benchmark
python -B -m AddressParser.build_uniform --out artifacts/baseline/new-uniform
```

Для `geonim_uniform` нужен дополнительный файл
`artifacts/baseline/v3/uniform-v3/uniform.sqlite`. Переопределение —
`JANA_UNIFORM_DB` или `AddressParser(uniform_path=...)`. Города допускаются после
исключения каждого дома из свидетельств: точность ≥99%, нижняя граница Wilson
≥97%, ≥100 прогнозов на ≥10 геонимах. Дополнительно проверяются наборы алиасов.
Неизвестные районы известных домов и конфликты блокируют вывод. Разные алиасы
одного номера/корпуса считаются одним домом. Evidence содержит `house_count`,
inferred-метод — `geonim_uniform`. Это проверка на метках самого справочника,
не независимая проверка географии.

Однозначный район может дать `city` и `province` с методом `district_parent`;
явное название города не заменяется этим выводом. Для обычных улиц минимум —
три дома. Для территорий и микрорайонов справочника порог два принят в Алматы,
Актобе, Таразе и Шымкенте после сравнения с порогом три по каждому городу.
В Астане выборка территорий недостаточна. При скрытии удаляется весь ключ дома
у всех алиасов. У «Аксай-3А» основной вывод — Ауэзовский район по контуру;
два домовых ключа сохранены в evidence.corroborating_uniform.

Контуры читаются из таблицы territory_districts того же runtime v002, который
выбран через JANA_ADDRESS_DB / db_path. Старый отдельный контурный файл больше
не используется. Необязательный JANA_TERRITORIES_DB / territories_path должен
указывать полный совместимый runtime v002, а не прежний вспомогательный индекс.
Для микрорайона/территории, включая отдельно указанный ЖК, основным методом
является `territory_within_district` при доле площади ≥95%. `geonim_uniform`
вычисляется для проверки согласованности и служит запасным, когда контура нет
или его покрытие недостаточно. Конфликт контура/домов блокирует оба метода;
разные районы дают null с district_methods_disagree в reasons и обоими
свидетельствами в diagnostics.district_lookup. Неполные метки домов не
запрещают принятый контур. Точный дом и явный район сохраняют приоритет.
Доля площади территории не является вероятностью района конкретного дома.
Полная проверка:

```text
python -B -S -m unittest AddressParser.test_parser AddressParser.test_evaluate AddressParser.test_neighbours AddressParser.test_regressions AddressParser.test_boundaries_v3 AddressParser.test_city_scope AddressParser.test_runtime_v002 AddressParser.test_cf_edges AddressParser.test_findings_v7 AddressParser.test_findings_v8 AddressParser.test_findings_v9 AddressParser.test_findings_v10 AddressParser.test_findings_v11 AddressParser.test_findings_v12 -v
```
Явно созданный экземпляр можно закрыть методом `close()` после работы.

Python 3.11+; проверено на Python 3.14.3 под Windows. Внешних зависимостей нет.
Все команды ниже запускаются из корня репозитория. Пути по умолчанию вычисляются
от расположения пакета, а не от текущей рабочей директории.

```python
from AddressParser import parse_address, explain_address, parse_records

record = parse_address('Ул .Курильская 9 кв 1')
explanation = explain_address('Ул .Курильская 9 кв 1')
records = parse_records([
    {'id': 'same', 'raw_address': 'Абая 1'},
    {'id': 'same', 'raw_address': 'Туран 2'},
])
```

`parse_address` возвращает ровно 14 ключей, `id=None`. Вход должен быть строкой.
Пакет принимает список объектов с `raw_address` и `id`, сохраняет порядок и
буквальные значения id/raw. Идентификаторы не участвуют в извлечении.
Некорректные типы входов вызывают исключение; HTTP-слой должен валидировать их.

## Поставка

Обязательны пакет `AddressParser` и файл
`artifacts/address_db/runtime/v002-territories/address_runtime.sqlite` (65 667 072 байта).
Путь можно задать переменной `JANA_ADDRESS_DB` либо `AddressParser(db_path=...)`.
Для соседнего вывода нужен `artifacts/baseline/neighbours-v1.sqlite`, или путь
`JANA_NEIGHBOURS_DB` / `neighbours_path`. Если слоя нет, остаются точные связи.
Он воспроизводится из открытого слоя справочника:

```text
python -B -m AddressParser.build_neighbours --out artifacts/baseline/neighbours-v2.sqlite
```

Новый выход должен отсутствовать. Сборка сверяет хеши шардов, берёт только
города/источники, разрешённые опубликованной политикой. Исходные артефакты
не изменяются. Для runtime не нужны dev, тесты, полные источники справочника,
построитель слоя, оценщик и бенчмарк. В контейнере следует задавать абсолютные
пути к трём SQLite явно: v002, neighbours-v1 и uniform-v3. Справочники
открываются только для чтения. V001 сохранён только для сравнения в отчёте;
в актуальный архив runtime он не входит.
Готовность контейнера и совместимость с его Python проверяет роль интеграции.

## Контракт пояснений

`parse_address(raw) == explain_address(raw)['record']` при одной конфигурации.
`spans` — список `{field,start,end}`, `sources` — словарь `string`/`dictionary`.
Индексы — кодовые точки Python str, конец не включён. Браузер должен переводить
их в UTF-16 перед нарезкой строки с символами вне BMP. Поля отсутствующих
значений в `sources` опущены. UI может брать `record` как `result`, остальные
ключи — как `explain`. Пример адаптации реализован в пакетной команде `--explain`.

Дополнительно возвращаются `span_map`, `origin`, `methods`, `evidence`,
`reasons`, `candidates`, `diagnostics`. Вырезаемые значения сохраняют raw:
никаких исправлений улицы, литер, падежей, внутренних невидимых знаков или NFKC.
Краевые Cf, пробелы и `,;:.` исключаются из значения и его интервала.
`province` использует профиль project. Явный `city` сохраняет написание строки
без маркеров, включая казахские, латинские и исторические имена. В двуязычном
дубле выбирается русская часть из строки. Выведенный город использует project.
Справочное обогащение во всех случаях использует ID найденного населённого пункта.
Для выведенного значения всегда заданы метод и справочное свидетельство.

## Конфигурация и расширение

`AddressParser(variant='B', beam_width=8)` — основной вариант.
Вариант A использует те же маркеры и распознавание административных имён,
но отключает справочное ранжирование улиц и вывод района. Это абляция роли
справочника, а не совершенно бессловарный парсер.

Административные и явно маркированные части ограничивают поиск. Сначала
ограниченный поиск разрешает числовые роли, затем совместно выбирает названия
улицы/жилого массива. Справочник даёт бонус кандидатам названия; не переписывает
их поверхность. Это ступенчатый декодер, не полный глобальный поиск всех разборов.
Список кандидатов и зазор оценок доступны для проверки. Рейтинг confidence
эвристический, не вероятность: учитывает заполненность, непокрытый текст,
числовые конкуренции, зазор и подтверждение названия справочником.

Поставщик `provider` реализует протокол из `contracts.py`. Сериализуемые tokens
содержат исходные позиции. Дополнительные кандидаты конкурируют с полученными
явными полями в общем интервальном декодере; после выбора справочное обогащение
выполняется заново. Базовый вариант не импортирует дополнительных моделей.
Перед закрытой проверкой расширенной конфигурации требуется отдельный manifest.

`mapping_path` принимает только явно заданный JSON формата `confidence-mapping/1`,
описанного в `contracts.py`. Меняется лишь численный рейтинг. Публичное отображение
калибровки не получено, не прочитано и не включено. Для другой схемы нужен адаптер.

Объект `AddressParser` использует SQLite-соединение потока создания. Для другого
потока создавайте отдельный экземпляр. Функции верхнего уровня автоматически
используют локальный для потока экземпляр. Кешируются только компонентные запросы
к справочнику; готовые ответы по всей входной строке не кешируются.
Индекс имён для сверки опечаток строится при первом открытии снимка в процессе
и повторно используется экземплярами. Он содержит только строки и разделён
по городам; SQL-соединения не разделяются. На приёмочном замере первый запуск
занял 0,541 с, полный разбор 1000 различных строк — 0,982 с.

## Оценка и ограничения

CLI оценщика открывает dev T3.1_A1 либо отдельно разрешённый train; сверяет
manifest dev и сохраняет хеш фактически прочитанного train.
Общая функция `evaluate.score(rows, predictions, config, eligibility=...)`
принимает уже загруженные позиционно согласованные данные. Веса берутся из config.
Чувствительность считается отдельными цельными сценариями, не выбором лучшего
ответа. Отчёты хранят основные метрики, ошибки, происхождение входов и срезы.

Синтетический dev — материал разработки, не оценка на реальных адресах.
Восемь прежних расхождений explicit city на dev исправлены сохранением
казахских и сельских названий; это улучшение на материале разработки.
Сэмпл совпадает по извлекаемым полям; район Ауэзовский выведен по контуру
территории с подтверждением однородных домов. При нескольких жилых территориях
контракт вмещает только одно значение. Произвольные склейки всех частей без
разделителей и неизвестные сокращения требуют дальнейших предметных проверок.
