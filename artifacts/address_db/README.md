# Справочник адресов: из чего и как собран

Сервис использует один файл: [`runtime/v002-territories/address_runtime.sqlite`](runtime/v002-territories/README.md) (66 МБ, Git LFS). Здесь лежат скрипты, которыми он собран из открытых источников. Для работы сервиса они не нужны: только для воспроизведения и обновления справочника.

## Источники

Полный каталог со ссылками, датами и условиями: [`scripts/sources/sources_catalog.json`](../../scripts/sources/sources_catalog.json).

| Источник | Что берём | Файл после скачивания |
|---|---|---|
| OpenStreetMap, выгрузка Geofabrik `kazakhstan-latest.osm.pbf` (снимок 15.10.2026) | Улицы, дома, микрорайоны, границы населённых пунктов и районов | `Data/research/raw/osm_kazakhstan_pbf.bin` |
| КАТО, Бюро национальной статистики РК, XLSX от 18.09.2026 | Официальные области, районы, населённые пункты, коды | `Data/research/raw/stat_kato_xlsx.bin` |
| Геопортал Карагандинской области | Улицы и адресный реестр Караганды для проверки | `Data/research/karaganda_*.json` |

Справочник ничего не скачивает во время работы. Источники загружаются один раз скриптом [`scripts/sources/fetch_sources.py`](../../scripts/sources/fetch_sources.py), который сохраняет ответы как есть и ведёт манифест контрольных сумм (`download_manifest.json`).

## Этапы сборки

| Этап | Скрипт (`artifacts/address_db/tools/`) | Что делает |
|---|---|---|
| 1. Извлечение | `extract_country_v3.py` | Читает PBF целиком, без географического фильтра: границы, улицы, дома, территории с идентификаторами и тегами OSM |
| 2. Перепись и контроль | `pbf_census_v1.py`, `contract_controls_v1.py` | Сколько чего в исходнике, проверка правил контракта |
| 3. Сборка страны | `build_country_v5.py` (+ `build_base_v1.py`, `db_common_v1.py`) | Сопоставляет OSM с КАТО: населённые пункты, геонимы, дома, районы, старые и казахские названия |
| 4. Приёмка выпуска | `verify_release_v1.py`, `sqlite_reference_v1.py` | Проверка инвариантов, замер скорости, промежуточный SQLite |
| 5. Связи и соседи | `relation_support_v2.py`, `neighbour_validation_v2.py` | Дом → район по точным связям и по соседним домам той же улицы, проверка вывода по соседям |
| 6. Поставка | `publish_delivery_v1.py` | Манифест выпуска с контрольными суммами |
| 7. Отображение названий | `build_display_release_v1.py` + `display_rules_v1.json` | Проектная форма названий (Абайская, Жетысуская, Улытауская области, Конаев) и официальная форма КАТО |
| 8. Компактный runtime | `build_runtime_index_v1.py`, `verify_runtime_index_v1.py` | Один файл SQLite, который читается стандартной библиотекой Python |
| 9. Территории → район | `build_territories_v2.py`, `verify_territories_v1.py`, `build_runtime_territories_v1.py` | Контуры микрорайонов и ЖК; район назначается, если в нём не меньше 95% площади территории. Конфликтные территории помечаются и не используются |

Этапы 1–6 запускаются одной командой из корня рабочей папки, где лежит `Data/research/raw/` с исходниками:

```bash
pip install -r artifacts/address_db/tools/requirements-build.txt
python AddressParser/build_address_db.py --release v011-rebuild
```

Этапы 7–9: команды в [`runtime/v002-territories/README.md`](runtime/v002-territories/README.md). Каждый этап создаёт новую версию в отдельной папке и никогда не перезаписывает существующую. Полный проход по PBF занимает десятки минут и несколько гигабайт промежуточных файлов, поэтому промежуточные выпуски в git не хранятся.

## Чтение справочника

`runtime_index_v1.py` и `runtime_territories_v1.py` — читатели runtime-файла: поиск геонимов, домов, района по дому и по территории. Парсер использует ту же схему через `AddressParser/reference.py`. Таблицы и поля: [`SCHEMA.md`](SCHEMA.md).

## Известные ограничения

- Полнота зависит от OpenStreetMap: дом, которого нет в OSM, не найдётся по точному номеру.
- В OpenStreetMap нет границ районов Караганды, поэтому там район не восстанавливается, а берётся только из строки.
- 95% площади территории в одном районе не означает, что каждый её дом в этом районе: этот способ используется, только когда нет точной связи дома.
